# Codex vendor HID evidence — 2026-10-04

Board: existing Freenove FNK0104B, native USB initially attached to WSL as
`/dev/ttyACM0`, 303a:1001. This record applies to the combined monitor, not a
substitute retail Codex Micro or another ESP32 board.

## Confirmed

- PlatformIO Core CLI `codex-monitor` build passed with Arduino 3.3.12 / IDF
  5.5.5 and the existing pinned platform. No toolchain migration.
- `pio run -e codex-monitor -t upload --upload-port /dev/ttyACM0` succeeded.
  Bootloader, existing partition table, existing speech models and final app
  hashes were verified. Final app length: 3,080,736 bytes. Post-write reset passed.
  No erase-all/eFuse/security changes; monitor NVS and partition boundaries retained.
- Windows `usbipd list` after reset:
  ```text
  3-1  303a:8360  USB Input Device, USB Serial Device (COM9)  Not shared
  ```
  This confirms physical HID+CDC composite enumeration with the intended VID/PID.
- `pio test -e native`: 24 passing tests, including descriptor contract and
  framing/protocol cases. Existing host/server suites: 5 and 60 passing tests.
- `codex-hid-diag` final build passed; diagnostic not uploaded because it uses
  a different partition profile.

## Initial capture gaps (historical)

The USB identity change detached the original WSL USB/IP attachment. PlatformIO
serial monitoring at 115200 baud was attempted after upload and failed because
`/dev/ttyACM0` no longer existed. The new Windows identity was not shared.
The owner was given the bind/attach commands to restore access for runtime checks.

Application startup, display/touch, live Wi-Fi/SSE and speech alongside HID,
host descriptor readback, protocol round trips, Codex Desktop discovery/status,
input acceptance, disconnect/reconnect and Wi-Fi-outage independence are UNKNOWN.
USB enumeration occurs before application setup and does not prove all of these.

See [the engineering report and checklist](../../docs/codex-hid.md) for commands
and evidence required to close each item. No full compatibility claim is made.

## Follow-up results

The owner subsequently confirmed Desktop discovery. The final audio follow-up
verified board startup, display, speech and Wi-Fi/SSE coexistence, healthy Windows
HID/CDC/audio interfaces, and a live device.status request with a completed reply.
Physical HID input acceptance, Desktop slot status, reconnect and Wi-Fi-outage
independence remain unverified. See [the current validation record](codex-audio-2026-10-04.md).
