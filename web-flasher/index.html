Configure your powered board

Connect through your browser

Use desktop Chrome on macOS, or Chrome / Microsoft Edge on Windows, with Bluetooth enabled. Open this HTTPS page directly in that browser. Safari and Firefox cannot use this page's Web Bluetooth controls.

Click the connect button below and choose the board in the browser's device picker. Monitor firmware advertises automatically; there is no pairing button and you do not need to pair it in Windows or macOS Bluetooth settings.

Can't find the board?

On Windows 11

  1. Turn on Bluetooth in Windows Settings and keep the board nearby and powered.
  2. Open this page in Windows Chrome or Edge. A site served from WSL can use Windows Bluetooth through that browser.
  3. Click Connect to monitor and look for FNK0104B-MONITOR in the browser picker. Older firmware may advertise Codex Micro.

On macOS

  1. Use desktop Chrome and turn on Bluetooth.
  2. In System Settings → Privacy & Security → Bluetooth, allow Google Chrome if it is listed. Accept a Bluetooth permission prompt, then restart Chrome if you changed its permission.
  3. Search using this page's connect button. Use the browser picker rather than the macOS Bluetooth settings list.

Switching computers? Close the connected settings tab on the other computer first. The monitor stops advertising while connected and resumes when it disconnects. If it still does not appear, restart the board, close the picker and open it again.

Wrong page or a redirect? Open the direct setup link. If your browser still redirects to another domain, clear site data for cmwen.github.io and cmwen.dev and retry.

For monitor firmware

Monitor settings

Connect to a board running monitor firmware to read or save its alert volume, idle screen timeout and USB Micro layout. Choose FNK0104B-MONITOR in the browser picker; OS pairing is unnecessary. The screen stays on while agents are active or voice commands are in progress. Once idle, it turns off after the configured time; touch or new agent activity wakes it. Values are saved on the board and persist across reboots.

These controls are unauthenticated: a nearby Bluetooth client can change these preferences. They do not accept Wi-Fi credentials. Use the protected Wi-Fi setup section below for passwords. Monitor bridge host/key are configured separately.

Choose three stable Desktop slots with four direction buttons, or all six slots. Click Save settings to apply the layout without reboot and keep it across restarts. This selects visible controls, not the number of running agents. Older firmware needs an update if this selector stays disabled.

Direction buttons send joystick input rather than keyboard arrow presses. Map their actions in Desktop’s Settings → Codex Micro under analog-stick directions. Tap the board’s Micro header indicator for the six command keys. Follow the custom button mapping guide.

For the monitor or Wi-Fi over BLE firmware

Set up Wi-Fi

The monitor opens setup when no Wi-Fi is saved. To change networks, hold its Wi-Fi indicator for three seconds. Read the 12-character code on the board, then connect below. The standalone Wi-Fi over BLE firmware also works.

ⓘ Check that this is the trusted HTTPS setup page. The device name alone does not prove identity. Enter the code from your own board and wait for “Connected securely” before entering a password. The code authenticates an encrypted provisioning session; this page does not save your password. The monitor returns automatically after setup.

For the Codex monitor

Run the local server

The board polls a Python bridge on your computer over Wi-Fi. This website handles Bluetooth settings; the bridge supplies live Codex status and usage. Keep the board and server on a network where they can reach each other.

  1. Save Wi-Fi on the board. Use the Wi-Fi setup section above if needed. The monitor reuses those saved credentials.
  2. Set the bridge address and key. Copy apps/codex-monitor/include/monitor_secrets.example.h to monitor_secrets.h in the same directory. Set MONITOR_SERVER_HOST to your computer's LAN IPv4 address, port to 8765, and token to a generated private key. The local launcher reads the same file.
  3. Start the bridge from the repository root in the environment with your running, signed-in Codex app-server: 
    MONITOR_HOST=0.0.0.0 MONITOR_LOG_REQUESTS=1 python3 monitor-server/run.py
    Keep that terminal running. Allow TCP 8765 on your trusted LAN. Optional voice commands require a separately running speech service; the full guide includes its launch settings.
  4. Build and flash your configured monitor from the repository root: 
    pio run -e codex-monitor
pio run -e codex-monitor -t upload
pio device monitor -b 115200
    Look for monitor_status integration=connected and numeric quotas. The bridge should log board requests to /v1/status returning HTTP 200.

Host/key are compiled into firmware and cannot currently be changed through Web BLE. The public monitor firmware has no private bridge configuration; use your local build to connect to the real server. Changing host/key requires rebuilding and uploading.

Running the server in WSL?

Windows browser Bluetooth access and the board's Wi-Fi access to WSL are separate. In WSL 2 NAT mode, localhost working on Windows does not make the bridge reachable from the board. Configure Windows TCP forwarding to WSL and allow the port through the private-network firewall. Use the Windows LAN address in the board header, not localhost or WSL's NAT address.
